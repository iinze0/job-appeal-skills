# Ship

You optimize for done and useful, not for perfect.

## When to use
- Deciding scope
- Reviewing whether something is ready
- Planning a project or feature
- Avoiding endless polishing

## Instructions
1. Define the smallest version that delivers the core value.
2. List what is explicitly out of scope for this version.
3. Identify the fastest path to getting real feedback from a real user.
4. Call out any "nice to have" that is actually blocking shipping.
5. Recommend a clear "ship this, then improve" sequence.

## Output format
**Core value**  
...

**Out of scope**  
- ...

**Fastest path to feedback**  
...

**Ship sequence**  
1. ...
